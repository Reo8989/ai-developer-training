## Bossの成り立ち：壊れたリポジトリの作り方（進行AI用・学習者には絶対に見せない）

`broken-repo-samples`（設計書 06 B-3）はまだ存在しないため、v1では**進行AIがこのBossの開始直前に、学習者の実リポジトリへその場で3件のCommitを作る**方式で代替する（`PRODUCTION_GUIDE.md` §6 判断12）。学習者には「AIに依頼した結果として3件積まれていた」という体で提示する。**壊し方の手順そのもの・どのCommitが問題かは、課題文にもヒントにも書かない。**

**手順（進行AIがこのBoss開始前に、学習者のリポジトリのmain上で直接実行する）**

1. Commit A（正しい・残すべき）：`CHANGELOG.md` に以下相当の1エントリを追記してCommitする。
   - 例：`## v0.4` の下に `- LEVEL 3（Branch / Merge / Conflict / Revert）の演習を追加` のような1行
   - Commit message例：`Update CHANGELOG for v0.4 LEVEL 3 additions`
2. Commit B（問題・これが原因）：`README.md` の見出し構造を壊し、同じCommitで `notes/level03-cli.md` を削除する。
   - README.mdの壊し方：すべての `#` `##` `###` の見出し記号を取り除き、目次と本文の区別がつかない1つの塊に見えるようにする。冒頭のタイトル行も無関係な文字列に差し替える。
   - Commit message例：`Restructure README and clean up notes`（一見もっともらしい、しかし中身は破壊）
3. Commit C（正しい・残すべき）：`notes/glossary.md` に、学習者がまだ書いていない用語（例：「HEAD」）を1件、4欄形式または学習者自身の言葉で追記してCommitする。
   - Commit message例：`Add HEAD entry to glossary`

**Push は各Commitごとに行い、3件とも履歴に残す（squashしない）。順序はA→B→Cを厳守する。問題のCommitを真ん中に置くのは、「最新のCommitを1件取り消せば済む」という安易な解法を封じるため。**

このあと、学習者には📢予告してから「今日、AIに作業を頼んだ結果を確認してほしい」という体で気づかせる（下記「課題文」参照）。

## 想起質問と模範解答（Boss開始前の確認）

`opening-boss-01.md` で既に出題済み。回答が届いたら、ここで答え合わせをしてからチェックポイントに入る。**先に模範解答を送らない。**

**質問と模範解答（学習者には見せていない前提）**

1. Q. `revert` と `reset` は何が違いましたか？
   A. `revert` は「訂正印を押して差し戻す」操作で、取り消したという記録が新しく1つ積まれ、履歴は消えない。`reset` は「記録ごと破り捨てる」操作で、本教材では扱わない。
2. Q. diff（差分）で、ある行が「削除1行＋追加1行」として表示されるのはどんなときでしたか？
   A. 1行だけ書き換えた場合。Gitは「変更後の全体」ではなく「元の行を消して、新しい行を足した」という形で差分を見せる。

**採点方針**：2問とも、正確な用語でなくても「差し戻す／記録が残る」「1行変えると削除＋追加で見える」の趣旨が言えていればOK。**部分点で褒める。** 曖昧なら、Mission 3-1・3-6のときの比喩（赤線・訂正印）に一度戻ってから先に進む。

> 🎯 **今回のミッション（Boss課題）**

> あなたのリポジトリに、AIに依頼した結果として3件のCommitが積まれています。そのうち2件は正しく、1件だけが問題を起こしています。**正しい2件を保ったまま、問題の1件だけを取り消し、動く状態に復旧してください。**

### CP3：正しい2件の変更を保ったまま復旧する（目安20分）

> 📢 **予告**：これから、原因のCommitだけを取り消します。GitHub DesktopのHistoryタブで該当のCommitを右クリックすると `Revert changes in commit`（このコミットの変更を取り消す）という項目が出ます。**`reset` は使いません。** revertは新しいCommitを1つ積んで取り消す操作なので、履歴は消えず、あとからでもやり直せます。

> **あなたはどう思いますか？** revertを実行すると、正しい2件（CHANGELOG.mdとnotes/glossary.mdへの追記）はどうなると思いますか。実行する前に予想を書いてください。

<details><summary>💡 ヒント1：方向（どこを見るか）</summary>

GitHub DesktopのHistoryタブで、CP2で特定した「原因のCommit」を探してください。そのCommitの上で右クリックしたときに出るメニューを見てみましょう。
</details>

<details><summary>💡 ヒント2：手順（何をするか）</summary>

1. Historyタブで原因のCommitを右クリックする。
2. `Revert changes in commit`（このコミットの変更を取り消す）をクリックする。
3. 新しいCommitが1件、履歴の一番上に積まれたことを確認する。
4. README.mdの見出しが元に戻り、notes/level03-cli.mdが復活していることを確認する。
5. CHANGELOG.mdとnotes/glossary.mdへの追記が、そのまま残っていることを確認する。
6. 右上のボタン `Push origin`（GitHubに送る）を押す。
</details>

<details><summary>💡 ヒント3：答え（完全な手順）</summary>

原因のCommitに対して `Revert changes in commit` を実行すると、そのCommitで行われた変更（README.mdの見出し破壊とnotes/level03-cli.mdの削除）だけが打ち消されます。CHANGELOG.mdとnotes/glossary.mdへの追記は**別のCommitで行われたものなので、revertの対象にはならず、そのまま残ります。** これがCommitを分けて積んでおくことの意味です。実行後は必ず `Push origin` でGitHubにも反映してください。**手元（ローカル）で直しただけではGitHub上はまだ壊れたままです。同期ではなく郵送なので、発送（Push）しない限り相手には届きません。**
</details>

**採点方針**：自動判定できる事実（revert Commitが履歴に存在する／CHANGELOG.mdとnotes/glossary.mdの追記が残っている／notes/level03-cli.mdが存在する／`reset --hard` が使われていない）で機械的に確認する。**`reset` を使った形跡があれば、この時点で不合格として扱い、やり直しを促す（減点ではなくrevertでの再挑戦を促す）。**

## 完了条件

以下**5つすべて**を満たすこと。

1. 3件のCommitの内容を差分から説明できた（CP1）
2. 原因のCommitを特定し、根拠を文章で示せた（CP2）
3. 正しい2件の変更（CHANGELOG.mdの追記・notes/glossary.mdの追記）が失われていない（CP3）
4. README.mdが読める状態に戻り、notes/level03-cli.mdが復活している（CP3）
5. 復旧手順が `notes/recovery.md` に文書化されている（CP4）

## 判定方法

自動判定に使ってよいのは「ファイル／リポジトリの存在」「revert Commitの有無」「履歴が壊れていないこと」などの**事実**だけ（CO-29）。コード内容の静的解析（文字列一致でのチェック）には依存しない。

**① 自動判定（事実の確認のみ）**
- `notes/recovery.md` が存在する
- revert Commit（`Revert changes in commit` によるCommit）が履歴に存在する
- CHANGELOG.mdとnotes/glossary.mdの追記が残っている
- notes/level03-cli.mdが存在する（復活している）
- 履歴が壊れていない（`reset --hard` が使われていない）

**② AIレビュー（進行AIが読んで判断）**
- CP2の「原因特定の根拠」が、差分の事実に基づいているか（推測だけになっていないか）
- `notes/recovery.md` の記録が、次に同じことが起きたときに再現できる粒度か

**③ 自己申告（学習者に確認する）**
- 何分かかったか
- どこで一番迷ったか

**すべて満たせば合格。①のいずれか1つでも欠けていれば不合格として、該当CPからやり直す。** `reset` を使ったことが判明した場合も不合格とし、「今回の変更を一度revertで整理してから、もう一度CP3をやり直しましょう」と伝える（リポジトリの作り直しは提案しない）。**再挑戦は何度でも可。**
