## 元構想からの主要な設計変更（要旨）

1. **LEVEL 0〜16 → LEVEL 0〜17・5 PHASE に再構成。** HTML/CSSをGitより前に前倒し（管理したい対象を先に作る）、認証をGitHub APIより前に移動（トークン直書き事故の防止）、Backend/Databaseを2 LEVELに分割。
2. **Seed App方式。** 「学習アプリを最初から作る」は鶏と卵問題になるため、依存ゼロの配布アプリ（v0.1）を学習者が育てる方式に変更。教材アプリは v0.1→v7.0 の成長表で全LEVELに紐付け。
3. **AI会社は12部門 → 5役割 + Orchestrator に縮小。** 12部門は管理・APIコストに対して教育効果が飽和するため。
4. **Docker / Python仮想環境 / Webhook自作 / OAuth自作 / Rebase を削除。** 初学者の到達ゴールに不要と判断（根拠は00 第4章）。
5. **技術スタックは3段階導入。** STACK A（素のHTML/CSS/JS + localStorage + GitHub Pages）→ STACK B（Next.js 16 + Vercel + Supabase）→ STACK C（AI / Agent）。「学習した技術だけを使う」原則に整合。
6. **Human-in-the-loopをコードで強制。** Merge API・シェル実行Toolは実装しない。承認なしのWriteは型レベルで不可能な設計。
7. **【改訂】STACK A の実行モデルを確定。** 正典は「GitHub Pages の公開URL」（LEVEL 2 以降）。ローカル開発は VS Code Live Server 拡張（npm不要・拡張1つ）を LEVEL 1 の最後に導入する。`index.html` ダブルクリックでの起動は `file://` の `fetch` 制限により LEVEL 6 で確実に破綻するため廃止（CO-01）。
8. **【改訂】LEVEL 7〜8 の GitHub PAT は `sessionStorage` 保持に変更。** アプリの設定画面から入力し、タブを閉じると消える。`location.hostname` が `localhost`/`127.0.0.1` のときのみ入力欄を有効化し、公開URL上では無効化する。`.env.local` は LEVEL 9 で使う仕組みの予習として位置づけを変更（CO-01）。
9. **【改訂】MVP を「MVP-0」「MVP-L」の2層に分離。** MVP-0＝制作者が最初に作る配布物、MVP-L＝学習者が LEVEL 8 終了時点（v2.0）で手にしているアプリ。「MVP」という語は STACK A の見出しからは外した（CO-02）。
10. **【改訂】教材制作は7STEPフル形式を40 Mission（高リスク地点）に限定。** 残り93 Mission は圧縮形式（01 6.2）。圧縮するのは分量であって構造ではなく、STEP 0・STEP 5 は圧縮形式でも省略しない（CO-03）。
11. **【改訂】卒業判定を T1〜T3 → T1〜T4 に拡張。** T1 を「未知コードベース参入テスト」（未知の OSS リポジトリの Issue に対する修正方針を PR 下書きで提出）に変更し、T4「統治実績確認」（AI に処理させた Issue 3件以上・差し戻し1件以上・`decisions/` への記録）を新設。ただし T1・T4 は能力軸レーダーの昇格には使わない（軸昇格は T2→C軸 Lv4、T3→D軸 Lv4 のみ）（CO-19）。

## 残課題

- **P2（余力があれば）6件は見送り。** 画面20→14削減／BLACKOUT 5→3回削減／AI解説モード段階開示／`ai-company` 保護パス化／Advanced トラック（Docker判断ガイド・Webhook自作・MCP自作・RAG・Rebase・SQL最適化）。D0〜D7 完了後に個別 CO を起票して再検討する（06 第5章 5.3）。
- **実装時に決定すればよい運用上の未決事項が6件残っている**（正典判定が未確定という意味の「要判断」ではない）。教材コンテンツの独自ブロック記法（`:::why` 等）の構文（A-3作成時）／Markdownレンダラの選定（D4）／LEVEL 6で使う公開APIの選定（B-5作成時）／B4・T1で使う外部API・リポジトリのプール（B-2作成時）／AIプロバイダの既定値（D5）／06第2章の制作工数試算の較正係数（D1終了時）。詳細は `revision/change_orders.md` 末尾を参照。
