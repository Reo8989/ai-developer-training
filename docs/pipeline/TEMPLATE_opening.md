# TEMPLATE_opening.md ― オープニング文面（受講者に最初に送る文面）標準テンプレート

> **このファイルは何か**：セッション開始時に、進行AI（Claude）が学習者へ **最初に送る1通の文面** を書くための雛形です。内部台本（`TEMPLATE_lesson.md` 由来の `mission-NN-N.md`）とは明確に分離します。
> **誰がいつ使うか**：
> - **生成AI**が、台本1本につき1通のopeningを書き起こすときにこの雛形を使います。
> - **進行AI（受講セッションのClaude）**は、セッション冒頭でこのファイルの「送信本文」ブロックを**ほぼそのままコピーして送信**します。
> - **学習者（MooNさん）**が実際に読む唯一の教材ファイルです。台本のほうは見せません。
> **出力先**：`content/level{NN}/opening-{NN}-{N}.md`
> **対になるファイル**：`content/level{NN}/mission-{NN}-{N}.md`

---

## なぜopeningを台本から分離するのか（この方式の根拠）

Day2の実運用で機能したことが根拠です。

1. **内部台本には模範解答が書いてある。** STEP 0 の想起質問を台本ごと見せると、答えが先に見えてしまい、想起テストが成立しない。
2. **AIが「小出しにする」判断を毎回する必要がなくなる。** 送る文面が確定していれば、進行AIの揺らぎ（説明しすぎ・先出ししすぎ）が構造的に防げる。
3. **学習者が読む量が固定される。** 300行を超える台本を渡されると圧倒される（実測：フル形式 360〜380行、圧縮形式 250〜390行）。openingは常に画面1〜2スクロール分（40〜70行）に収まる。
4. **中断からの復帰点になる。** 数日空いたとき、学習者はopeningだけ読み返せば再開できる。

**opening に書いてよいのは4つだけ**：①声かけ ②STEP 0 の想起質問2問 ③今日の予告 ④最初の一手。**答え・解説・用語定義・手順は書かない。**

## 記入例（Day2 実運用の再現）

Day2 で実際に機能した文面を、このテンプレートに当てはめた例。**迷ったらこの水準に寄せること。**

````markdown
MooNさん、お疲れさまです。今日は **「本番を壊さずに試して、あとから本番に反映する」やり方** をやります。

### まず、思い出すところから

前回（設計書一式の公開）の内容を **教材を見ずに** 答えてみてください。うろ覚えでも大丈夫です。

**Q1.** GitHub Desktopで Commit ボタンを押した直後、変更した内容はどこに保存されていますか？

**Q2.** `.gitignore` に書いたファイルは、GitHub Desktop の画面上でどうなりますか？

### 今日やること

「ブランチ」という、本番のコピーを1部取って安全に試す仕組みを使います。コピーの上で編集して、問題なければ本番に合流させるところまでを一周します。そのあと、**わざと衝突（Conflict）を起こして、自分で解決します。** 30〜40分くらいの想定です。疲れていたら後半は次回に回して大丈夫です。

> 📢 **今日の予告**：今日は途中で **わざと衝突を起こします。** `<<<<<<< HEAD` のような見慣れない記号が画面に出ますが、**これは失敗ではなく予定された演習**です。必ず解決できますし、解決の手順こそが今日の学習内容です。
> もうひとつ、GitHubに送るボタンの表示が、前回の `Push origin` ではなく **`Publish branch`** になります。これは「まだGitHub上に無いブランチを初めて公開する」ときだけの表示です。押して大丈夫です。

### 今日新しく覚える言葉

Branch / Merge / Conflict（3語だけです）

### 最初の一手

GitHub Desktop を開いてください。

上のQ1・Q2に答えてから、教えてください。分からなければ「わからない」でも大丈夫です。そこから一緒に思い出します。
````

## opening を書くときの禁止事項

| # | 禁止 | 理由 |
|---|---|---|
| O-1 | 想起質問の答えを書く | 想起テストが成立しない |
| O-2 | 用語の定義を書く | STEP 1 の対話（予想させてから渡す）が成立しない |
| O-3 | 操作手順を2ステップ以上書く | 学習者が先走って台本の順序を飛ばす |
| O-4 | 予告なしで「⚠ 意図的失敗」の回を始める | 予告のないエラーは「自分には向いていない」という一般化された結論を与える（06 3.1） |
| O-5 | 学習者名・GitHubユーザー名をファイルに直書きする | 他の受講者に使い回せなくなる。`{{学習者名}}` のままにして、送信時に `docs/CONTEXT.md` §2 から差し込む |
| O-6 | XP・スキルバー・進捗率を主役に置く | 表示の主役は「できるようになったこと」（00 R-01） |
| O-7 | 3語を超える新出用語を列挙する | 作業記憶の制約（00 5.3.1） |
| O-8 | 「簡単です」「すぐ終わります」と書く | 詰まったときに「簡単なはずのことができない」という自己否定になる |
