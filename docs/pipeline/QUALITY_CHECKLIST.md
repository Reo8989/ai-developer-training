# QUALITY_CHECKLIST.md ― レッスン台本 品質チェックリスト

> **このファイルは何か**：生成されたレッスン台本（`mission-NN-N.md`）とオープニング（`opening-NN-N.md`）が、教育設計・カリキュラム設計・改訂指示書（CO-01〜CO-32）の要件を満たしているかを **レビューAIが機械的に判定する** ための合否基準集です。
> **誰がいつ使うか**：
> - **レビューAI**が、生成直後の台本を採点するとき（`PRODUCTION_GUIDE.md` §3 のループの STEP 2）。
> - **生成AI**が、自分の出力を提出する前のセルフチェックとして。
> - **人間（MooNさん）**が受講テスト後に「なぜ詰まったのか」を構造側に帰す手がかりとして。
>
> **判定の出し方**：各項目に `PASS` / `FAIL` / `N/A` を付け、FAIL には「どの行が・どう違反しているか」を1行で書く。
> **合格基準**：**Aブロック（禁則事項）に1件でもFAILがあれば不合格**（修正必須）。Bブロック（構造）は FAIL 0件で合格。Cブロック（品質）は FAIL 2件以内で合格（3件以上は書き直し）。

## 注記：CHK-C13（分量）の改訂について（2026-08-16）

**旧値**：フル形式 150〜280行／圧縮形式 50〜100行。

**改訂した理由**：序盤コース10レッスン（LEVEL 3 ＋ BOSS 1 ＋ LEVEL 4 前半）を10名の制作者が並行生成した結果、**12本すべてが旧値を超過**した（圧縮形式の実測 246〜377行、フル形式 360〜377行、Boss形式 312行）。制作者全員から「Bブロック（構造要件）の必須項目を1つも省略せずに満たすと、必然的に旧値を超える」という同一の報告が上がった。

実際に、Bブロックが圧縮形式にも義務づけている固定コストだけで旧値の上限を超える：

| 必須要素 | 出典 | 最低行数の目安 |
|---|---|---|
| メタ情報テーブル10行＋新出用語行 | CHK-B01 | 約15行 |
| 参照ディレクティブ6行 | CHK-B04 | 約8行 |
| 使い方メモ 共通7項目＋固有1行 | CHK-B05 | 約10行 |
| STEP 0（質問2問＋模範解答＋採点方針） | CHK-B07 | 約12行 |
| STEP 4 の3段階ヒント（`<details>`×3） | CHK-B18 | 約25行 |
| STEP 5（★仮説欄／選択肢4つ／❌✅対比／8項目テンプレート／プロンプト例3件） | CHK-B20〜B23 | 約55行 |
| STEP 6（なぜ型3問＋`<details>`解答3件） | CHK-B24, B25 | 約25行 |
| STEP 7（Commit型＋実例2件＋成長ログ＋public注意＋成果物＋CONTEXT更新） | CHK-B26〜B28 | 約30行 |
| 🎉 完了表示（5項目の優先順位つき） | CHK-B29 | 約10行 |
| 制作メモ欄 | CHK-B30 | 約10行 |
| **小計（STEP 1・2・3 と 🔍 なぜ？ を1行も書かない場合）** | | **約200行** |

**したがって、旧値の「圧縮形式50〜100行」は Bブロックと構造的に両立しない。** 旧値は「圧縮するのは分量であって構造ではない」（`TEMPLATE_lesson.md` §3）という原則が確定する前に置かれた目安であり、Bブロックの側が正しい。**レッスンを削って旧値に合わせるのではなく、目安値を実態に合わせて改訂する**という判断を採った。

**新値の根拠**：実測値（圧縮 246〜377／フル 360〜377／Boss 312／opening 48〜50）に、上下方向の余裕を約±10%取ったもの。**上限は「必要以上に書き足していないか」の警告線**として機能させる（上限超過は即FAILではなく、まず「STEP 2 の手順が細かすぎないか」「🔍 なぜ？ の設計思想を2箇所以上書いていないか（`TEMPLATE_lesson.md` は1レッスン1箇所と定めている）」を点検する）。

**次に見直すタイミング**：受講テストで「読む量が多すぎて進行AIが小出しにできていない」という観測が2レッスン以上で出たら、分量ではなく **Bブロックの必須項目そのもの**を減らす議論に進む（`PRODUCTION_GUIDE.md` §3-6 の「2回起きたらチェックリストを直す／3回起きたらテンプレートを直す」に従う）。
